## Topic: Nmap service enumeration — practice note

Today I reviewed how to move from discovering open ports to understanding the services running on them. This entry is a study example; the sample output below is illustrative and is not from a live target scan.

## 1. Why service detection matters

An open port tells me that something is listening. It does not, by itself, prove which exact application or version is running. Service detection helps gather more detail so I can choose the next enumeration step based on evidence.

## 2. Commands to understand

```bash
# Default scripts and service/version detection on a lab target
nmap -sC -sV <TARGET_IP>

# Save the scan output for later review
nmap -sC -sV -oN nmap-basic-scan.txt <TARGET_IP>

# Check all TCP ports (can take longer)
nmap -p- <TARGET_IP>
```

- `-sC`: runs Nmap's default set of safe-enough discovery scripts; scripts can still interact with services, so use them only on authorized targets.
- `-sV`: probes open ports to identify service and version details.
- `-oN`: saves output in normal text format.
- `-p-`: scans all TCP ports from 1 through 65535.

## 3. Illustrative output

A scan might report entries such as:

```text
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH ...
80/tcp open  http    Apache httpd ...
```

This is only an example to explain the columns:
- **PORT** identifies the port and protocol.
- **STATE** reports Nmap's observed state.
- **SERVICE** is the service name associated with the port.
- **VERSION** is the version information Nmap was able to identify.

I should not assume that every service label or version guess is perfectly accurate. I need to validate important findings with appropriate follow-up checks.

## 4. My enumeration workflow

1. Confirm that the target is the machine assigned to my authorized lab.

4. Research and enumerate each exposed service separately.
5. Keep evidence and actual command output in my notes.
6. Avoid jumping to exploitation before I understand the service.
