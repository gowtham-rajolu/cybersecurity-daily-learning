## Nmap — options I was trying to understand

I asked about scanning a list of IPs and what options like `-sC`, `-sV` and `-p` actually do.

```bash
# Scan selected ports on an authorised lab machine
nmap -p 22,80,443 <lab-ip>

# Try to identify service versions
nmap -sV <lab-ip>

# Run default NSE scripts as well as version detection
nmap -sC -sV <lab-ip>

# Read targets from a text file
nmap -iL targets.txt
```

My takeaway: `-p` chooses ports, `-sV` probes services to identify versions, `-sC` runs Nmap's default script set, and `-iL` reads targets from a file. The target list still needs to be within the lab scope.

I need to get better at reading the output instead of treating an open port as proof of a vulnerability. A version string is a clue to investigate, not a final finding.

## The difference between the tools

I was mixing up whether Metasploitable is a tool like Nmap or Wireshark. The distinction is:

- **Nmap:** discovers hosts, open ports and services.
- **Wireshark:** captures and inspects network packets.
- **Burp Suite:** lets me inspect and modify web traffic while testing an application.
- **Metasploit:** a framework with modules used during security testing.
- **Metasploitable:** the deliberately vulnerable machine I can use as a practice target.

So Metasploitable is the lab target, not a scanning tool.

## VPN and network checks

I had trouble reaching a lab target even though the VPN appeared connected. These commands help me check the local interface and routing table:

```bash
ip -br addr
ip route
ip route get <lab-ip>
ping -c 4 <lab-ip>
ss -tulpn
```

Important point I learned: a VPN interface showing UP doesn't automatically mean the route to the target is correct. Also, ping can fail because ICMP is filtered. I should check the route and the specific lab service rather than conclude the machine is down from ping alone.
