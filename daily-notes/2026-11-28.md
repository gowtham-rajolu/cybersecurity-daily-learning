# 28 November 2026 — Linux file types and identification

Today I studied how Linux represents file types and how to identify them from the command line. I also connected this to filesystem enumeration used during Linux security assessments.

## 1. Linux file types

The first character in the long listing from `ls -l` indicates the filesystem object type:

| Symbol | Type | What it represents |
|---|---|---|
| `-` | Regular file | Text files, scripts, binaries and other ordinary files |
| `d` | Directory | A container for directory entries |
| `l` | Symbolic link | A reference that points to another path |
| `c` | Character device | A device accessed as a stream of characters |
| `b` | Block device | A device accessed in blocks |
| `p` | FIFO / named pipe | A one-way inter-process communication channel |
| `s` | Unix-domain socket | A local inter-process communication endpoint |

Example:

```bash
ls -l
```

Example listing:

```text
-rwxr-xr-x 1 user user 1200 script.sh
drwxr-xr-x 2 user user 4096 Documents
lrwxrwxrwx 1 user user   10 shortcut -> script.sh
```

Read the first character: `-` is a regular file, `d` is a directory and `l` is a symbolic link.

## 2. Commands for identifying and inspecting files

### `ls -l` — listing and type indicator

```bash
ls -l
```

Shows the file-type character, permissions, link count, owner, group, size, modification time and name.

### `file` — identify content format

```bash
file script.sh
```

This examines a file's contents and reports a likely format, such as a Bash script or ELF executable. It is different from the first character in `ls -l`: `ls` reports the filesystem object type, while `file` identifies the data format/content.

### `stat` — detailed metadata

```bash
stat script.sh
```

Displays metadata including file type, permissions, ownership, size and timestamps.

## 3. Why file types matter in security enumeration

When checking for SUID executables, limit the search to regular files:

```bash
find / -type f -perm -4000 2>/dev/null
```

Breakdown:

- `find /` — search from the filesystem root.
- `-type f` — match regular files only.
- `-perm -4000` — match files with the SUID permission bit set.
- `2>/dev/null` — discard permission and traversal errors from standard error.

SUID (Set User ID) can cause an executable to run with the file owner's effective user ID. It is not automatically a vulnerability; investigate the owner, file, version, configuration and how the program behaves before drawing conclusions.

## 4. Searching for files modified yesterday

Linux `find` can filter files by timestamps. To search for regular files modified during yesterday's calendar day (according to the machine's local timezone):

```bash
find /path/to/search -type f -newermt "yesterday" ! -newermt "today" 2>/dev/null
```

- `-newermt "yesterday"` selects files modified after yesterday began.
- `! -newermt "today"` excludes files modified at or after today's start.
- `-type f` limits the results to regular files.

For files modified within the last 24 hours, use:

```bash
find /path/to/search -type f -mmin -1440
```

Do not confuse `-mtime 1` with “yesterday”: it means a modification age of one completed 24-hour period (roughly 24–48 hours ago), not a calendar date.

### Modification time versus creation time

- `mtime`: when file contents were last modified.
- `ctime`: when file status/metadata last changed; it is not creation time.
- `atime`: when the file was last accessed.
- Birth/creation time: available only when the filesystem and tools expose it.

To inspect the timestamps reported by the filesystem:

```bash
stat filename
```

A file's modification date does not reliably tell you when it was originally created. Also, Git tracks committed snapshots and commit timestamps, not the original local filesystem creation time.

## 5. Commands to practise

Run these on a Linux machine or an authorised lab:

```bash
ls -l
file /bin/bash
stat /bin/bash
find /usr -type f -perm -4000 2>/dev/null
find ~ -type f -newermt "yesterday" ! -newermt "today"
```

For each result, identify the filesystem type, explain what the permissions mean and distinguish file metadata from the file's content format.

## 6. Key takeaways

- The first character in `ls -l` indicates the filesystem object type.
- `file` identifies likely content formats; it does not replace `ls -l`.
- `stat` provides detailed metadata.
- `find -type f -perm -4000` is useful when enumerating SUID regular files.
- `find -newermt` is useful for calendar-date modification searches; `-mmin` is useful for elapsed-time searches.
- A SUID bit deserves investigation, but its presence alone does not prove an exploitable weakness.
