## Session focus
Investigating the web application's file-upload behaviour and understanding the difference between uploading a file and executing it on the server.

## Environment
- Attacker machine: Windows
- VPN-side address observed: `192.168.161.231`
- Target address used in this session: `10.48.186.54`
- Web server banner observed: Apache/2.4.41 (Ubuntu)

## Enumeration observations
- Discovered `/panel/` as the file-upload interface.
- Discovered `/uploads/` with directory listing enabled.
- Uploaded `rs.sh`; it appeared in the uploads directory.
- Opening `/uploads/rs.sh` in a browser displayed the script as text.
- An upload attempt using the `.php` extension was blocked by the application.

## What I learned
1. A successful upload only confirms that a file was stored.
2. Apache serving a `.sh` file as text does not execute it.
3. Bash scripts require a Bash interpreter and a server-side process that runs them.
4. Upload validation and server-side execution are separate behaviours.
5. A reverse shell is a way to receive a connection after code execution; it does not create the initial execution vulnerability.

## Commands and tools reviewed
Windows network inspection:
```cmd
ipconfig
route print
```

Linux file permissions and execution concepts:
```bash
ls -l <filename>
chmod +x <filename>
./<filename>
```

The Linux commands above require an authorized shell on the Linux host; they cannot be run by opening the uploaded file's URL.
