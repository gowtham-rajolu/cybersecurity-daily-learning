## File upload points to remember

Things I need to check when studying an upload feature:

- Does the server check the extension, MIME type and actual file content?
- Can the application rename uploaded files?
- Where does it store them? Is that location served by the web server?
- Can uploaded files be executed, or are they served only as downloads?
- Are file size and permissions restricted?

A browser-side check is not enough. The server has to enforce the rules too. A safer design stores uploads outside the executable web root, uses generated filenames and allows only formats the application needs.

## Python virtual environment

I also had questions about creating a virtual environment on Ubuntu. These are the commands I want to keep handy:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
deactivate
```

The point is to keep project packages separate from the system Python. Ubuntu can report that the system environment is externally managed; using a venv is the normal way around that for a project. I shouldn't force-install packages globally just to get past that warning.

## grep commands I looked up

```bash
grep "error" app.log
grep -i "failed" auth.log
grep -n "login" app.log
grep -r "TODO" ./project
grep -E "401|403|500" access.log
```

- `-i` ignores case.
- `-n` prints line numbers.
- `-r` searches directories recursively.
- `-E` enables extended regular expressions.

I still need to practise these on real sample logs so I can recognise useful output without guessing.
